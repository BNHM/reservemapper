About ReserveMapper

Spatial searches for biodiversity records

ReserveMapper performs an exact spatial polygon search for GBIF occurrence records and spatial bounding-box searches for supporting services. Observations without coordinates, or that are purposefully obscured (e.g. for endangered species) or that have low accuracy may not appear in ReserveMapper results. Occurrence and checklist data are harvested from third-party web services, including the Global Biodiversity Information Facility, which serves data from the Berkeley Natural History Museums and other institutions. Photo searches use CalPhotos.

This site was made possible by a grant from the University of California Division of Agriculture and Natural Resources.

Occurrence Searches

Occurrence searches return individual GBIF occurrence records that match the selected polygon and any filters in the sidebar. These are specimen, observation, or related biodiversity records with coordinates.

  • The map shows returned records as points or clustered points. Clicking a point opens the interpreted record details and a GBIF link.
  • The table is a record-level view. Counts in the Statistics tab use GBIF facets when available, so large result sets can be summarized beyond the visible table sample.
  • CSV downloads are capped at 100,000 records. For complete datasets beyond that cap, use the corresponding GBIF occurrence download workflow.

Checklist Searches

Checklist searches build an observed-species checklist from GBIF occurrence records inside the selected polygon. This is a derived checklist, not a curated flora, fauna, or management checklist.

  • Each checklist row represents a GBIF taxon, usually a species, found in occurrence records for the selected area.
  • occurrence_count is the number of GBIF occurrence records supporting that checklist row, not the number of taxa.
  • Scientific names and higher taxonomy are resolved from the GBIF taxon service. First and last year fields are derived from supporting occurrence records when evidence has been loaded.
  • Use checklist results as an evidence-based starting point. Missing coordinates, obscured records, taxonomic changes, duplicate records, and uneven collecting effort can all affect what appears.

Interpreting Results

ReserveMapper searches across external services, so results depend on the quality, coverage, and current availability of those services. A missing record does not necessarily mean a taxon is absent from an area, and a returned record should be checked against its source when precision matters.

  • Occurrence results are best interpreted as source records with coordinates in or near the selected area.
  • Checklist results are best interpreted as taxa inferred from matching GBIF occurrence records.
  • CalPhotos results are image records from CalPhotos and may use broader bounding-box spatial matching.

Polygon Sets

The selected area list is driven by polygon files. By default, ReserveMapper loads University of California Natural Reserve polygons, but the same application can load other polygon sets representing parks, preserves, watersheds, counties, campuses, project areas, or any other spatial areas.

To call ReserveMapper with another polygon set, provide a GitHub contents path in the URL using the layers parameter and set the dropdown name with title. For example: ?layers=json&title=University%20of%20California%20Natural%20Reserve. Each listed polygon file should be GeoJSON that the application can draw on the map and use as the spatial filter for occurrence and checklist searches.
